# SonarQube analysis

WinCapture contains a .NET 10 API, a React/Vite/TypeScript SPA, an Angular Albums app, and xUnit/Vitest tests. Run SonarScanner for .NET from the repository root so it can collect C# analysis during MSBuild and multi-language analysis for the frontend files. The scanner's multi-language mode includes TypeScript, JavaScript, CSS, HTML, and JSON; generated dependency and build directories are excluded below.

## Prerequisites

- A SonarQube Server project and a server version compatible with the installed SonarScanner for .NET.
- A project analysis token provided through `SONAR_TOKEN` and the server URL in `SONAR_HOST_URL`. Do not put the token in source control or command history.
- .NET 10 SDK and Node.js 22.

Install the scanner once:

```powershell
dotnet tool install --global dotnet-sonarscanner
```

Set the host URL and token in the current shell using your organization's secret store. The project key below is `WinCapture`; change it in `begin` if your SonarQube project uses another key.

## Full analysis

Run from the repository root in PowerShell:

```powershell
dotnet sonarscanner begin /k:"WinCapture" /d:sonar.host.url="$env:SONAR_HOST_URL" /d:sonar.token="$env:SONAR_TOKEN" /d:sonar.projectBaseDir="$PWD" /d:sonar.scanner.scanAll=true /d:sonar.exclusions="**/node_modules/**,**/dist/**,**/build/**,**/.angular/**,**/bin/**,**/obj/**,**/TestResults/**,**/coverage/**,**/Migrations/**,**/*.Designer.cs,frontend/public/msal-redirect-bridge.min.js" /d:sonar.cs.opencover.reportsPaths="backend.Tests/**/coverage.opencover.xml" /d:sonar.javascript.lcov.reportPaths="frontend.Tests/TestResults/lcov.info,angular-frontend.Tests/TestResults/lcov.info"
dotnet build backend/WinCapture.csproj --configuration Release --no-incremental
dotnet test backend.Tests/WinCapture.Tests.csproj --configuration Release --collect:"XPlat Code Coverage" --settings backend.Tests/coverlet.runsettings
Push-Location frontend
npm ci
npm run lint
npm run test:coverage
npm run build
Pop-Location
Push-Location frontend-angular
npm ci
npm run typecheck
npm run test:coverage
npm run build:production
Pop-Location
dotnet sonarscanner end /d:sonar.token="$env:SONAR_TOKEN"
```

The coverage reports are generated by the existing test tools: OpenCover plus Cobertura for .NET, and LCOV for both frontend test suites. Coverage no longer excludes application `Program.cs`, models, or DTOs; only migrations and generated/compiler files are omitted from the .NET coverage report. Do not add exclusions to lower a reported issue or to inflate coverage.

The repository solution file currently fails a direct solution-level `dotnet build` without diagnostics in this environment, so the analysis sequence builds the API and test project explicitly. If this is corrected or the solution builds in your environment, using `dotnet build WinCapture.slnx --configuration Release --no-incremental` inside the scanner session is also appropriate.

## Review results

The scanner end step uploads findings to the configured server. Review new issues in the project's configured quality profile and gate; resolve real bugs and maintainability issues in source. Do not add `NOSONAR`, broad exclusions, or rule suppressions just to make the gate green. This repository has no SonarQube server URL or token, so no server analysis is run by the local build/test workflow.
